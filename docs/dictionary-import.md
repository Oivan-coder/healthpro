# Импорт лабораторного справочника

Документ описывает безопасную загрузку большого лабораторного справочника в «Атлас здоровья».

## Формат

Импортёр ожидает 14 колонок:

1. Наименование исследования
2. Наименование теста
3. Биоматериал
4. Единицы измерения
5. Референс нижний
6. Референс верхний / текстовый референс
7. Референсная группа
8. Критическое значение ниже
9. Критическое значение выше
10. Метод
11. Раздел
12. Подраздел
13. Синонимы русский
14. Синонимы английский

CSV-парсер поддерживает запятые, точки с запятой и табуляцию как разделитель, экранированные кавычки и переносы строк внутри quoted-полей.

## Важное правило подготовки

В production-режиме импортёр **не наследует автоматически** название теста, биоматериал, единицы, метод, раздел или подраздел из предыдущей строки. Пустое поле остаётся пустым.

Это сделано намеренно: старый forward-fill мог незаметно присвоить новому тесту единицу, метод или исследование от предыдущей строки.

Для старых исходников, в которых пустые повторяющиеся ячейки действительно означают «как строкой выше», оставлен явный совместимый режим:

```bash
--legacy-forward-fill
```

Его следует использовать только после отдельной проверки исходника. Для подготовленного production-справочника этот флаг не нужен.

## Preview без записи в БД

Из папки `backend`:

```bash
npm run dictionary:inspect backend/import/dictionaries/lab_dictionary_full.csv
```

Проверка показывает:

- количество логических строк;
- количество колонок;
- уникальные исследования;
- уникальные тесты с учётом контекста;
- связи исследование–тест;
- строки с референсами;
- строки без биоматериала и единиц как информационные показатели;
- строки `needs_review`.

При необходимости проблемные строки можно выгрузить:

```bash
node src/import/dictionaryImport.js inspect backend/import/dictionaries/lab_dictionary_full.csv --export-review=tmp/dictionary-review.csv
```

## Что блокирует импорт

Строка переводится в `needs_review`, в частности, если:

- отсутствует исследование;
- отсутствует тест;
- число колонок отличается от 14;
- у одного теста в одном контексте конфликтуют единицы;
- числовой нижний референс больше числового верхнего;
- нижнее критическое значение больше верхнего.

По умолчанию наличие хотя бы одной строки `needs_review` **блокирует импорт целиком**. Это защита от частичной незаметной загрузки испорченного справочника.

`--allow-review` оставлен только для осознанного частичного импорта: проблемные строки будут сохранены в staging и пропущены при загрузке основных таблиц.

## Импорт в MySQL

Перед импортом схема должна быть применена:

```bash
cd backend
npm run db:init
```

После успешного preview:

```bash
npm run dictionary:import backend/import/dictionaries/lab_dictionary_full.csv
```

Импорт выполняется транзакционно и:

- сохраняет исходные строки в `lab_dictionary_import_rows`;
- делает upsert в `lab_services`;
- делает upsert в `lab_tests`;
- создаёт связи `lab_service_tests`;
- добавляет справочные референсы в `lab_test_references` без дублей;
- не удаляет существующие demo-данные;
- повторный запуск не должен создавать дубли.

## Контекстные тесты

Тест не считается уникальным только по названию. Для идентичности учитываются:

- название теста;
- биоматериал;
- раздел / подраздел;
- временная точка;
- метод.

Поэтому, например, эритроциты в крови и моче — разные сущности, а один тест может входить в несколько исследований через `lab_service_tests`.

## Референсы

Референсы из справочника сохраняются в `lab_test_references` как справочные fallback-данные.

Они не считаются универсальной медицинской истиной: конкретный диапазон может зависеть от лаборатории, метода, оборудования, пола и возраста. Если ЛИС/МИС передаёт референс вместе с конкретным результатом пациента, такой референс имеет приоритет.

Для импортированных словарных тестов поля `lab_tests.low_value/high_value` намеренно не заполняются из первой попавшейся референсной группы. Это предотвращает ситуацию, когда возрастной или половой диапазон ошибочно становится «общим» диапазоном теста.

Raw-значения референсов сохраняются всегда. Если граница безопасно разбирается как число, дополнительно заполняется numeric-поле. Значения вида `<5`, `>10`, `не обнаружено`, `отрицательно`, `следы` сохраняются как raw-текст.

## Staging и маппинг

`lab_dictionary_import_rows` хранит исходные и нормализованные значения и позволяет разбирать спорные строки без потери исходника.

`lab_source_mappings` предназначена для будущего сопоставления локальных кодов и названий разных МИС/ЛИС с нормализованными `service_id` и `test_id` Атласа.
