# Импорт лабораторного справочника

Документ описывает безопасный импорт большого лабораторного справочника в Атлас здоровья.

## Куда положить CSV

Основной путь:

```bash
backend/import/dictionaries/lab_dictionary_full.csv
```

CSV должен содержать 14 колонок:

1. Наименование исследования
2. Наименование теста
3. Биоматериал
4. Единицы измерения
5. Референс нижний
6. Референс верхний / текстовый референс
7. Референсная группа
8. Критическое значение ниже
9. Критическое значение выше
10. Метод
11. Раздел
12. Подраздел
13. Синонимы русский
14. Синонимы английский

## Preview без записи в БД

Из папки `backend`:

```bash
npm run dictionary:inspect backend/import/dictionaries/lab_dictionary_full.csv
```

Команда:

- читает CSV;
- определяет количество строк;
- проверяет количество колонок;
- применяет forward-fill для пустых значений исследования, теста, биоматериала, единицы, метода, раздела и подраздела;
- показывает первые 10 распознанных строк;
- считает уникальные исследования;
- считает уникальные тесты с учетом контекста;
- считает связи исследование-тест;
- считает строки с референсами;
- показывает строки `needs_review`.

Если команда запускается из папки `backend`, можно также указать путь короче:

```bash
npm run dictionary:inspect import/dictionaries/lab_dictionary_full.csv
```

## Импорт в MySQL

Перед импортом MySQL-схема должна быть применена:

```bash
cd backend
npm run db:init
```

Затем:

```bash
npm run dictionary:import backend/import/dictionaries/lab_dictionary_full.csv
```

Импорт:

- сохраняет все строки в staging-таблицу `lab_dictionary_import_rows`;
- делает upsert в `lab_services`;
- делает upsert в `lab_tests`;
- создает связи `lab_service_tests`;
- сохраняет справочные референсы в `lab_test_references`;
- не удаляет существующие seed-данные;
- не создает дубли при повторном запуске;
- спорные строки помечает как `needs_review`.

## Что такое staging

`lab_dictionary_import_rows` — это промежуточная таблица для безопасной загрузки.

Она хранит исходные значения CSV и нормализованные значения:

- raw-названия исследования и теста;
- raw-биоматериал, единицы, референсы, метод, раздел;
- normalized-названия;
- статус импорта;
- комментарий для ручной проверки.

Смысл staging: не грузить большой справочник вслепую в основные таблицы и не терять строки, которые требуют ручного разбора.

## Что такое needs_review

`needs_review` означает, что строку нельзя безопасно сопоставить автоматически.

Примеры:

- отсутствует исследование;
- отсутствует тест;
- количество колонок отличается от ожидаемых 14;
- у одинакового теста в одинаковом контексте отличаются единицы измерения.

Такие строки остаются в staging и не теряются. Их можно разобрать позже вручную и добавить правила маппинга.

## Контекстные тесты

Атлас здоровья не считает тест уникальным только по названию.

Для нормализации учитываются:

- название теста;
- биоматериал;
- единица измерения;
- контекст;
- временная точка;
- метод.

Примеры:

- `Эритроциты` в крови и `Эритроциты` в моче — разные тесты;
- `Глюкоза натощак`, `Глюкоза через 60 минут` и `Глюкоза через 120 минут` — разные тесты;
- один и тот же тест может входить в разные исследования, поэтому связь хранится отдельно в `lab_service_tests`.

## Референсы из справочника

Референсы из CSV сохраняются в `lab_test_references` как справочные fallback-данные.

Важно: они не являются абсолютной медицинской истиной для всех лабораторий.

Для конкретного результата приоритет имеют референсы, которые пришли из ЛИС/МИС вместе с результатом пациента. Справочник нужен для витрины, предварительной нормализации и случаев, когда источник не передал диапазон.

Raw-значения сохраняются всегда. Если значение безопасно парсится как число, дополнительно заполняется numeric-поле. Текстовые значения вроде `<`, `>`, `не обнаружено`, `отрицательно`, `следы` остаются raw-строками.

## lab_source_mappings

`lab_source_mappings` предназначена для будущего сопоставления кодов МИС/ЛИС с нормализованными сущностями Атлас здоровья.

В нее можно будет сохранять:

- исходный код услуги;
- исходное название услуги;
- исходный код теста;
- исходное название теста;
- биоматериал;
- единицы;
- временную точку;
- целевой `service_id`;
- целевой `test_id`;
- статус маппинга и confidence.

Это позволит подключать разные лаборатории, где одна и та же медицинская сущность может иметь разные локальные коды.
