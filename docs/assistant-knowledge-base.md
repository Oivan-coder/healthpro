# Ассистент Атласа — база знаний MVP

Ассистент Атласа в MVP v5.3 работает в безопасном AI/demo-safe контуре. По умолчанию включен mock provider: реальные языковые модели не вызываются, медицинские данные не отправляются во внешние сервисы. Для локальной integration-only проверки можно включить GigaChat provider через backend `.env`.

## Ограничения

- Ассистент не ставит диагноз.
- Ассистент не назначает лечение.
- Ассистент не заменяет консультацию врача.
- Ассистент отвечает только по результатам, подключенным в Атласе здоровья, и согласованным медицинским сценариям.
- Если вопрос выходит за рамки базы знаний, ассистент должен явно сказать, что сейчас не может отвечать на такие вопросы.

## Источник логики

Медицинская логика должна приходить из таргетных цепочек:

- сводка пациента перед приемом;
- интерпретация лабораторного результата;
- объяснение статуса показателя;
- подготовка вопросов врачу;
- маршрут записи к врачу;
- напоминание о границах ответственности.

LLM в будущей версии может использоваться только как слой объяснения: переформулировать уже согласованную цепочку понятным языком, не добавляя диагнозы, назначения или новые медицинские выводы.

## AI-ready конфигурация

Backend закладывает параметры:

```text
AI_ENABLED=false
AI_PROVIDER=mock
```

Mock включается так:

```text
AI_ENABLED=false
AI_PROVIDER=mock
```

GigaChat включается только на backend:

```text
AI_ENABLED=true
AI_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=
GIGACHAT_AUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
GIGACHAT_API_URL=https://gigachat.devices.sberbank.ru/api/v1
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
GIGACHAT_REJECT_UNAUTHORIZED=true
```

`GIGACHAT_AUTH_KEY` — auth/authorization data для Basic OAuth. Если есть только пара из кабинета Сбера, можно указать `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET`, backend соберет auth key сам. Если локально Node падает с `SELF_SIGNED_CERT_IN_CHAIN`, можно временно поставить `GIGACHAT_REJECT_UNAUTHORIZED=false`; для staging/production нужно вернуть `true` и подключить сертификат через `GIGACHAT_CA_CERT_PATH`. Секреты не хранятся во frontend и не должны попадать в README, docs, screenshots или архивы. OAuth token кэшируется в памяти backend до истечения срока действия и не логируется. Если внешний AI возвращает диагнозоподобные формулировки или упоминания лечения, backend включает safety guard и заменяет ответ на безопасный шаблон подготовки вопросов врачу.

## GigaChat integration safety

- Provider получает только минимальный контекст: вопрос пациента, режим ассистента, выбранный показатель или краткую сводку лабораторных данных.
- PDF-файлы, полный профиль пациента, телефон, полис, MIS card и лишние ПДн не отправляются в provider.
- Prompt ограничен по размеру.
- Если GigaChat недоступен, нет ключа, истек token или возник timeout, backend возвращает безопасный mock fallback и сохраняет совместимый response shape.
- Audit log фиксирует событие `assistant_chat` с provider/status/mode, но без полного текста вопроса и ответа.

Это не обученная медицинская модель и не врачебная интерпретация. Реальные медицинские сценарии, тексты и ограничения должны пройти врачебную валидацию перед пилотом.
