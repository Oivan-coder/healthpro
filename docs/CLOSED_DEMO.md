# Закрытый демо-контур

Текущая ветка готовит «Атлас здоровья» к закрытому тестированию с настоящей серверной авторизацией и только синтетическими данными.

## Принципы

- frontend не хранит признак авторизации;
- backend создаёт серверную сессию и передаёт браузеру HttpOnly cookie;
- пользователи, роли и сессии хранятся в MySQL;
- пароли хранятся только как scrypt-хеши;
- временный пароль обязательно меняется при первом входе;
- роли первой версии: `admin` и `user`;
- технические разделы и управление пользователями доступны только `admin`;
- production не использует JSON fallback;
- демо-контур содержит только синтетические данные.

## Локальная инициализация MySQL

1. Создать `.env` на основе `.env.example`.
2. Установить `USE_DB=mysql` и реквизиты MySQL.
3. Инициализировать схему и миграции:

```bash
npm run db:init
```

4. Загрузить синтетические медицинские данные:

```bash
npm run db:seed
```

5. Перед созданием тестовых учётных записей задать переменные окружения:

```text
DEMO_ADMIN_LOGIN=<admin login>
DEMO_ADMIN_PASSWORD=<temporary password>
DEMO_USER_LOGIN=<test user login>
DEMO_USER_PASSWORD=<temporary password>
DEMO_USER_DISPLAY_NAME=Иванов Иван Иванович
DEMO_USER_PATIENT_ID=p_001
```

6. Создать учётные записи в MySQL:

```bash
npm run db:seed:users
```

Пароли из переменных окружения в БД в открытом виде не записываются.

## Проверка перед публикацией

- admin входит по временному паролю и обязан сменить его;
- admin создаёт, блокирует и разблокирует пользователя;
- admin может сбросить пароль пользователя;
- user входит по временному паролю и обязан сменить его;
- user не видит раздел администрирования;
- запрос user к `/api/admin/*`, audit и техническим import endpoints получает `403`;
- после logout старая сессия больше не работает;
- после блокировки активные сессии пользователя отзываются;
- данные сохраняются после перезапуска backend;
- в production при недоступной MySQL backend не переключается на JSON.
